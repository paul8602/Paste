## 1. 迭代目标（0.3.0）

1. **macOS 可靠性补全**：完成 0.2.0 计划中余留的大内容哈希、显式事务、粘贴时序三项，消除高频使用场景下的已知缺陷。
2. **Windows 可发布品质**：在现有代码基础上通过实机验证、修复发现的问题，产出与 macOS 产品体验对齐的 Windows 安装包。
3. **UX 深度提升**：虚拟滚动（浏览全部历史）、搜索结果高亮、空状态引导、快捷键提示四项，使面板在历史积累 1000+ 条时依然可用。
4. **发布工程化**：版本号、CHANGELOG、平台已知限制文档化，双平台产物一致性验证。

非目标（本周期不强行纳入）：Linux 支持、云同步、多设备、插件体系、富文本预览。

## 2. 工作流划分

### A. macOS 可靠性与性能补全

| 编号 | 主题 | 内容 | 验收建议 |
|------|------|------|----------|
| A-1 | 大内容哈希 | 对 >1MB 的 payload 使用采样哈希（头 64KB + 尾 64KB + 总长度），同时保留精确哈希模式作为可选项 | 复制大图/大文件时 CPU 峰值可测下降；去重语义在 settings 中注明采样策略 |
| A-2 | 插入显式事务 | `insert_clip` 内用 `conn.execute_batch("BEGIN IMMEDIATE")` / `COMMIT` 包裹全部写操作 + prune，替代隐式自动事务 | 异常退出后 DB 无损坏；高频复制下写操作原子性可验证 |
| A-3 | 粘贴时序 | 替代固定 80ms sleep：写入剪贴板后轮询 `changeCount`（最多 200ms，步长 20ms），确认写入完成后发送粘贴键 | 慢速机器（Rosetta/VM）粘贴成功率不劣于现状；可配置超时上限 |
| A-4 | WAL 检查点 | 在 `save_settings` 时执行 `PRAGMA wal_checkpoint(TRUNCATE)`，控制 WAL 文件增长 | 长时间运行后 WAL 文件不超过 ~4MB |

### B. Windows 验证与修复（对齐 windows-support-plan）

按验证顺序建议：

| 编号 | 主题 | 内容 | 验收建议 |
|------|------|------|----------|
| B-1 | 实机构建验证 | 在 Windows 环境上 `npm run tauri:dev` 和 `tauri:build:win` 通过 | 构建零错误，产物可安装 |
| B-2 | 核心路径冒烟 | 复制文本 → 列表更新 → 搜索 → 粘贴到记事本，全程验证 | 核心路径无阻断 |
| B-3 | 窗口行为适配 | 验证透明窗口、alwaysOnTop、decorations: false 在 Windows 10/11 上的表现；必要时调整窗口风格 | 面板外观与 macOS 基本一致 |
| B-4 | 已知限制文档化 | 将 "已知限制" 表（图片格式差异、HTML header、快捷键冲突等）收入 README 或 wiki | 用户可在文档中找到平台差异说明 |

### C. UX 深度提升

| 编号 | 主题 | 内容 | 验收建议 |
|------|------|------|----------|
| C-1 | 虚拟滚动 / 分页 | 当前硬编码 40 条上限。改为：前端请求 40 条，滚动到底部触发加载更多（cursor-based）；或实现虚拟滚动使 1000+ 条流畅浏览 | 加载 500 条后滚动帧率 >30fps；搜索仍在前端模糊匹配（先加载全部 summary 再过滤） |
| C-2 | 搜索结果高亮 | `renderClips` 时对匹配字符加 `<mark>` 标签，使用 CSS 高亮样式 | 输入 "hel" 时列表中 "hello" 的 "hel" 部分视觉可区分 |
| C-3 | 空状态引导 | 首次启动（数据库为空）显示引导文案 + 快速示例文案 + 快捷键提示卡片 | 新用户无需读文档即可完成首次复制→粘贴 |
| C-4 | 快捷键提示 | 在面板底部或 hover 状态中显示可用快捷键（↑↓ 导航、1-9 快速粘贴、Enter 粘贴、Esc 关闭） | 快捷键可发现性提升 |
| C-5 | 列表项 tooltip | hover 列表项时显示完整文本预览 + 时间戳 | 截断文本可完整阅读 |

### D. 发布与工程化

| 编号 | 主题 | 内容 | 验收建议 |
|------|------|------|----------|
| D-1 | 版本号与 CHANGELOG | `tauri.conf.json` version → `0.3.0`；新建 `CHANGELOG.md` 记录自 0.1.0 以来的全部变更 | 版本号一致，CHANGELOG 覆盖所有用户可感知的变化 |
| D-2 | 双平台产物验证 | CI 产出 macOS universal DMG + Windows MSI/NSIS，验证安装和基本功能 | 每个产物至少经过一次手动冒烟 |

## 4. 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **虚拟滚动复杂度** | C-1 可能比预估多 2-3 天工作量 | 备选方案：先做简单的「加载更多」按钮，虚拟滚动推迟到 0.4.0 |
| **Windows 实机缺失** | B-2/B-3 验证依赖 Windows 物理机或 VM | CI 至少验证编译通过；Windows 冒烟可接受社区反馈 |
| **采样哈希去重精度** | 采样哈希可能导致不同内容被误判为重复 | 默认关闭采样，设为 opt-in；文档明确标注碰撞概率 |
| **Windows 窗口透明** | 部分 Windows 版本 DWM 行为不一致 | 添加非透明 fallback 模式，通过设置切换 |
| **快捷键冲突** | Windows 上 Ctrl+Shift+V 可能与某些应用冲突 | 文档标注已知冲突；快捷键可配置化纳入 0.4.0 |
